# Shake to Wake

A Flutter + native Android app that turns the screen ON by shaking the phone —
built for a Samsung Galaxy A10 whose hardware power/volume buttons are broken.

It runs a native Kotlin **foreground service** with a persistent notification
that listens to the **accelerometer** at all times (even while the screen is
off / device is asleep) and fires a **wake lock** the instant it detects a
shake gesture.

## 2. One-time setup (do this before opening the project)

Because the Flutter/Gradle wrapper binaries (`gradlew`, `gradlew.bat`,
`gradle-wrapper.jar`) and the `local.properties` file are machine-specific
and generated by the Flutter tool itself, generate them once like this:

```bash
# 1. Create a throwaway scaffold Flutter project to get the wrapper files
flutter create --platforms=android --org com.shakewake shake_wake_scaffold

# 2. Copy the generated wrapper files into THIS project
cp -r shake_wake_scaffold/android/gradlew        shake_wake_app/android/
cp -r shake_wake_scaffold/android/gradlew.bat    shake_wake_app/android/
cp -r shake_wake_scaffold/android/gradle/wrapper/gradle-wrapper.jar \
      shake_wake_app/android/gradle/wrapper/
cp shake_wake_scaffold/android/local.properties  shake_wake_app/android/

# 3. Delete the scaffold, you don't need it anymore
rm -rf shake_wake_scaffold
```

`local.properties` just needs two lines pointing at your SDKs, e.g.:

```
sdk.dir=/Users/you/Library/Android/sdk
flutter.sdk=/Users/you/dev/flutter
```

Then, from inside `shake_wake_app/`:

```bash
flutter pub get
flutter build apk --release
# or, with the phone plugged in via USB / adb over network:
flutter run --release
```

The generated APK will be at
`build/app/outputs/flutter-apk/app-release.apk`.

## 3. How the shake detection works (`ShakeForegroundService.kt`)

* Registers a `SensorEventListener` on `Sensor.TYPE_ACCELEROMETER` with
  `SensorManager.SENSOR_DELAY_GAME`. This keeps running even when the screen
  is off, because it lives inside a **foreground service**, not the UI.
* Converts the raw `(x, y, z)` accelerometer reading into a **g-force
  magnitude**. At rest this is ~1.0g; a shake produces a spike well above
  that.
* Requires **2 spikes** within a 3-second window (with basic de-bounce
  between them) before it counts as a deliberate "shake", not just someone
  picking the phone up.
* On a confirmed shake it acquires a
  `PowerManager` wake lock using
  `PowerManager.FULL_WAKE_LOCK | PowerManager.ACQUIRE_CAUSES_WAKEUP | PowerManager.ON_AFTER_RELEASE`
  for up to 8 seconds, which turns the screen on immediately, then releases
  it automatically.
  * Technical note: `FULL_WAKE_LOCK` and `SCREEN_BRIGHT_WAKE_LOCK` are both
    wake-lock **levels**, and Android only accepts one level per lock
    (levels can't be OR'd together — only a level + flag constants like
    `ACQUIRE_CAUSES_WAKEUP`/`ON_AFTER_RELEASE`). `FULL_WAKE_LOCK` already
    keeps the screen at full brightness, so combining it with those two
    flags is the correct, reliable way to get an instant "screen on"
    equivalent to a real power-button press.
* After waking the screen it ignores sensor input for 4 more seconds so a
  single shake doesn't repeatedly retrigger.
* A `NotificationCompat` low-importance, ongoing notification is shown the
  whole time the service runs (with a "Stop" action button), which is what
  keeps Android from killing the service in the background.
* Sensitivity is passed in from Dart as a **g-force threshold** (lower
  number = easier to trigger) and is also persisted to a native
  `SharedPreferences` file so `BootReceiver` can restore it after a reboot.

## 4. Permissions used (see `AndroidManifest.xml`)

| Permission | Why |
|---|---|
| `FOREGROUND_SERVICE` / `FOREGROUND_SERVICE_SPECIAL_USE` | Run the always-on shake listener as a real foreground service |
| `WAKE_LOCK` | Turn the screen on from the background |
| `RECEIVE_BOOT_COMPLETED` | Restart the service after the phone reboots |
| `POST_NOTIFICATIONS` | Show the required persistent notification on Android 13+ |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | Let the user exempt the app from battery-optimization killing |
| `DISABLE_KEYGUARD` | Declared for completeness; the service only wakes the screen, it does not bypass the lock screen's security prompt |

> This app deliberately does **not** try to dismiss/unlock the keyguard —
> it only turns the display on. If the phone has a lock screen (PIN,
> pattern, fingerprint), that will still show up as normal, exactly as it
> would if you had pressed a working power button.

## 5. Using the app

1. Launch the app, flip the **Shake service** switch ON.
2. Pick a sensitivity level from the dropdown (**High** = a gentle shake is
   enough, **Low** = needs a firm shake — useful if you carry the phone in a
   bag).
3. Tap the battery-optimization card and choose **"Don't optimize" /
   "Unrestricted"** for this app when prompted — this is essential on
   Samsung devices (One UI is aggressive about killing background services).
4. Lock the phone normally. When the screen turns off, shake the phone —
   the screen will turn back on.

---

## 6. Samsung-specific tip

Samsung's One UI has its own extra battery manager on top of stock Android.
In addition to the in-app "disable battery optimization" prompt, also open:

**Settings → Apps → Shake to Wake → Battery → Unrestricted**

and make sure the app is **not** listed under **Settings → Battery → Background
usage limits → Sleeping apps / Deep sleeping apps**.
